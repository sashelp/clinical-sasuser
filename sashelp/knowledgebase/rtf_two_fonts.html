如何同时输出宋体和新罗马字体？

SAS 一个单元格只能设一种字体，所以先按常规出 RTF，再把文件头的 \f1、\f2 改成宋体和 Times New Roman，并把正文的 \f1\ 换成 \f1\f2\。

结论

SAS 的样式选项是按单元格设字体的，一个单元格只能一种，做不到“中文宋体、西文新罗马”混排。但 RTF 文件本身支持：在字体表里把两个编号分别定义成两种字体，然后在正文文本前把这两个控制字连着写，Word 就会用前一个排中文、后一个排西文。落实成程序就是三步：正常出 RTF → 逐行读进来改字体表和正文的字体控制字 → 写回文件。

监管是怎么要求的

“电子申报资料的中文字体应为宋体，字号不小于小四号字，英文字体应为 Times New Roman，叙述性文本字号推荐为 12 号；表格中字号不小于五号字；行间距离至少为单倍行距。”

—— 国家药监局药审中心，《申报资料电子光盘技术要求》

如果在生成 TFL 时就把这条落实，团队标准统一，统计师也不用事后再调。字号和行距可以在 PROC REPORT 的样式选项或 PROC TEMPLATE 的模板里设，唯独字体混排这一条，靠样式选项做不到。

RTF 是怎么控制字体的

RTF 是纯文本，用记事本就能打开。它以 {\info …} 为界分成文件头和文档区，字体定义在文件头的字体表里，由控制字 \fonttbl 引出。用 SAS 出一份普通报表，文件头长这样：

{\fonttbl
{\f1\froman\fprq2\fcharset134\cpg936 CSongGB18030C-Light;}
{\f2\froman\fprq2\fcharset134\cpg936 Times;}
}

每个字体一项，编号 \f1、\f2 就是后续正文引用它时用的代号。文档区里，文本前出现 \f1\ 就表示“接下来的字用 1 号字体”。默认输出里几乎全是 \f1\，所以整篇都是一种字体。

同一个单元格里混排两种字体，靠的是“连着写两个控制字”

实现：出报表 → 改文件 → 写回

先正常生成一份 RTF。示例用 sashelp.class，标题和脚注里各放一段中英文混合文字，方便后面看效果：

ods rtf file="test.rtf";

proc report data=sashelp.class nowd style(report)={just=left width=100%
  pretext="这是标题部分 This is Title" posttext="这是脚注部分 This is Footnote"};
run;

ods rtf close;

然后读进来改。核心是两个动作：文件头里把两个字体项的名字换掉，文档区里把每个 \f1\ 换成 \f1\f2\。

data _temp_;
  infile "test.rtf" length=length;
  input rtf $varying32767. length;
  retain header_part 1;
  if header_part=1 then do;
    if rtf=:"{\f1\" then rtf=substr(rtf,1,anyspace(rtf))||"SimSun;}";
    else if rtf=:"{\f2\" then rtf=substr(rtf,1,anyspace(rtf))||"Times New Roman;}";
    if find(rtf,"{\info","t") then header_part=0;
  end;
  else rtf=tranwrd(rtf,"\f1\","\f1\f2\");
run;

data _null_;
  set _temp_;
  file "test.rtf";
  put rtf;
run;

这段代码在干什么

  1. infile … length=length + input rtf $varying32767. length：把 RTF 当纯文本一行一行读进来。length 是这一行的实际长度，$varying 按这个长度截取，避免定长读入带一堆尾随空格。
  2. retain header_part 1：一个开关，标记“现在还在文件头”。
  3. rtf =: "{\f1\"：=: 是“以……开头”的比较，不是等于。所以只匹配字体表里那一行。
  4. substr(rtf,1,anyspace(rtf)) || "SimSun;}"：anyspace 找第一个空格的位置，从行首截到空格为止，再接上新字体名和右花括号。相当于“保留前缀、换掉字体名”，\fcharset134\cpg936 这些控制字原样留着。
  5. find(rtf,"{\info","t")：碰到 {\info 就把开关关掉，后面的行都算文档区。"t" 是让比较时忽略尾随空格。
  6. tranwrd(rtf,"\f1\","\f1\f2\")：文档区里把字体控制从“一种”改成“两种”。这一步只作用于文档区，字体表那一行不会被重复替换。
  7. 第二个数据步：file + put 把改好的内容写回原文件。因为整份文件已经先读进 _temp_，写回同名文件不会互相干扰。

实测：改前改后对比

我在 SAS 9.4 上照这个流程跑了一遍，字体表的变化是：

位置改之前改之后
字体表第 1 项{\f1\…CSongGB18030C-Light;}{\f1\…SimSun;}
字体表第 2 项{\f2\…Times;}{\f2\…Times New Roman;}
正文 \f1\106 处105 处变成 \f1\f2\，剩 1 处在字体表里
文件行数279279（没有丢行）

再拿 Word 打开改后的文件，逐字符读字体属性：

字符Font.Name（西文）Font.NameFarEast（中文）
这 / 是 / 标 / 题…宋体宋体
T / h / i / s…Times New Roman宋体

同一个单元格里，中文走宋体、西文走新罗马，达到了想要的效果。

几个要注意的地方

  • 字体编号不是固定的。\f1、\f2 谁是谁，取决于 ODS 样式和模板。我这里的默认样式下 f1 是 CSongGB18030C-Light、f2 是 Times，和文章示例一致；换成自定义模板就得先打开 RTF 看字体表，别照抄编号。
  • 顺序不能反。前一个控制字管双字节（中文），后一个管单字节（西文）。写成 \f2\f1\，中文就变成新罗马了。
  • 只改文档区。靠 header_part 这个开关把文件头排除在外，否则字体表里的 \f1\ 也会被替换，越改越乱。
  • 依赖“一行一个字体项、字体名前有空格”。anyspace 就是靠这个空格定位的。ODS 默认输出是这样，自定义模板要确认。
  • 这是后处理。报表重跑一次就得再跑一次，建议把第二段包成宏，接在出报表之后自动执行。
  • 字体名写错不会报错。Word 找不到就回退到默认字体，看代码发现不了，只能靠打开文件确认。
  • 只管字体，不管字号和行距。小四、五号、单倍行距这些还在样式里设，别指望这段代码解决。
