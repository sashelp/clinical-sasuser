知识库 / 性能与调优

PROC MIXED / GLIMMIX 报内存不足或者跑几个小时，先改哪里？

先给足内存并按 subject 处理模型，再简化 DDFM 和协方差结构，最后才考虑换 HPMIXED。

结论

按顺序动四个地方：运行环境（memsize、关掉没用的程序、结果不进 Results 窗口、走 batch）、让过程按 subject 处理（这是最有效的一步）、换更省的选项（DDFM、协方差结构、少要输出）、换过程（HPMIXED）。多数情况下走到第二步就能看到明显改善，不要一上来就怀疑机器不够。

为什么会吃这么多资源

MIXED 和 GLIMMIX 是迭代算法，代价主要来自三处：数据量大、CLASS 变量水平数多、以及 PROC / MODEL / RANDOM / REPEATED 语句里选了耗费资源的选项。最典型的例子是随机效应水平特别多——比如每个受试者一个随机截距，几千个受试者，G 矩阵就几千维，如果过程没有按 subject 分块处理，就要一次性求一个巨大的矩阵。

第一步：把运行环境放开

先确认当前的 memsize 是多少，以及配置文件在哪：

proc options option=memsize value;
run;

日志会告诉你当前值和 sasv9.cfg 的路径。用文本编辑器（以管理员身份打开）改这一行，比如改成 memsize 16g，或者 memsize 0 用满可用内存。存盘之后必须新开一个 SAS 会话才生效，改完接着跑是不管用的。

另外三件顺手就能做的事：

  • 跑之前把没用的程序关掉，把内存让出来。
  • 如果程序会产生大量结果表（比如几千个 BY 组，或者宏里循环调用过程），加 ods noresults;，不让 Results 窗口去跟踪这些对象。
  • 改用 batch 模式提交，不要交互式跑。交互式会话要维护界面和结果树，本身就吃内存。

第二步：让过程按 subject 处理

这一步最见效。下面这种写法，B 的水平一多就容易崩：

proc mixed;
   class a b;
   model y=a;
   random b;
run;

统计上等价但数值上高效得多的写法是把它变成 subject 效应：

proc mixed;
   class a b;
   model y=a;
   random intercept / subject=b;
run;

这样 G 矩阵变成按 subject 分块的对角结构，过程可以逐个 subject 处理，内存和时间的增长从“水平数的平方”变成“水平数”。还能再进一步：如果 B 是数值变量（或者能方便地转成数值），先按 B 排序，再把 B 从 CLASS 里拿掉，效率更高：

proc sort;
   by b;
run;

proc mixed;
   class a;
   model y=a;
   random intercept / subject=b;
run;

如果模型能换成等价的 REPEATED 写法，也值得换。REPEATED 比 RANDOM 省内存，subject 水平多的时候尤其明显：

proc mixed;
   class a b;
   model y=a;
   repeated / subject=b type=cs;
run;

GLIMMIX 里同样的道理。下面两段，第二段把三个随机效应里都出现的 C 提出来当 subject，G 矩阵变成块对角，快很多：

proc glimmix;
   class a b c;
   model y=a b / ddfm=satterth;
   random c a*c b*c;
run;

proc glimmix;
   class a b c;
   model y=a b / ddfm=satterth;
   random int a b / subject=c;
run;

有几个 RANDOM 语句时还要注意：只有每个 RANDOM 都有 SUBJECT=，而且这些 subject 效应互相嵌套，过程才会按 subject 处理。条件不满足就退回整体计算。所以尽量让所有 RANDOM 和 REPEATED 用同一个、或者互相嵌套的 subject。

第三步：换更省的选项

选项怎么省
DDFM=RESIDUAL 或 DDFM=BW比 KR 省很多内存；SATTERTH、BW 通常比 CONTAINMENT 快
TYPE= 换简单结构UN 和空间结构最贵；重复测量次数多时改用 TOEP，随机系数模型改用 VC
去掉 NOBOUND出现负方差分量时算法会变复杂，资源消耗明显上升
NOCLPRINT不打印 CLASS 水平信息表，水平特别多时省内存也省时间
先不加 SOLUTION、OUTP=、OUTPM=、INFLUENCE、OUTPUT这些都要额外存储和计算。先用最简模型把模型跑通，确认没问题再逐个加回来
关掉 ODS Graphics画图本身也很吃资源，调模型阶段可以先不画

第四步：换过程

  • PROC HPMIXED：固定效应或随机效应有成千上万个水平，或者分层嵌套每层都有几百上千水平时用它。它专门为高维稀疏矩阵设计，代价是部分功能不支持。
  • Viya 的 PROC LMIXED：支持多线程和并行，数值上也更高效。
