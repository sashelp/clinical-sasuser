知识库 / 统计分析

干预前后两组比较，“差中之差”怎么估？交互项系数就是它吗？

普通线性模型里，交互项系数就是差中之差；换成 logistic 这类链接，交互项只是 log odds 尺度的差中之差，均值层面要另外算。

结论

差别在于链接函数。模型是恒等链接（REG、GLM、GENMOD 的默认设置）时，交互项系数就是均值之差之差，参数估计表里直接能看到，也可以用 ESTIMATE 或 LSMESTIMATE 写 1 -1 -1 1 复现。模型是 logit、log 这类非线性链接时，交互项估的是链接函数变换后的差中之差，想回到均值（概率）层面，必须对四个格子分别反变换再相减，这已经不是线性组合，要用 NLMeans、NLEST 或 Margins 宏。

先把“差中之差”写清楚

两个二分类变量 A 和 B，各有 1 和 0 两个水平，带交互项的模型是：

μAB = λ + αA + βB + γAB

“A 的效应在 B=1 时”减去“A 的效应在 B=0 时”，展开之后 λ、α、β 全部抵消：

(μ11 − μ01) − (μ10 − μ00) = γ

这就是差中之差。所以在这种模型里，你不用额外算什么，交互项本身就是答案。

恒等链接：交互项直接用

data a;
   sd=3;
   do a=1,0;
   do b=1,0;
      input mean @@;
      do rep=1 to 10;
         y=rannor(23425)*sd+mean;
         output;
      end;
   end; end;
   datalines;
50 70 40 40
;
run;

proc genmod;
   class a b / ref=first;
   model y = a b a*b;
   estimate "Diff in Diff" a*b 1 -1 -1 1;
   lsmeans a*b;
   lsmestimate a*b "Diff in Diff" 1 -1 -1 1;
run;

三个地方给的是同一个数：交互项参数、ESTIMATE、LSMESTIMATE，都是 −21，p<0.0001。四个格子的均值由 LSMEANS 给出，代回去也对得上：−21 ≈ (50−40) − (69−38)。要区间就在 LSMEANS 和 LSMESTIMATE 后面加 CL，得到 (−24.3, −17.7)。

系数 1 -1 -1 1 的排列顺序是 LSMEANS 输出里四个格子的顺序：A1B1、A1B0、A0B1、A0B0。顺序换了，正负号就变了，报结论时最好写清楚是“谁减谁”。

前后测的纵向数据：先把数据结构改对

实际研究通常是同一个受试者干预前测一次、干预后测一次。这时每个人有两条记录，用 GEE 处理同一个人内部的相关系：

data a;
   keep exposed id post y;
   set a;
   Post=1; y=y_post; output;
   Post=0; y=y_pre;  output;
run;

proc genmod;
   class id exposed post / ref=first;
   model y = exposed post exposed*post;
   repeated subject=id(exposed);
   estimate "DID Post(E-U)-Pre(E-U)" exposed*post 1 -1 -1 1;
   lsmeans exposed*post;
   lsmestimate exposed*post "DID Post(E-U)-Pre(E-U)" 1 -1 -1 1;
run;

注意 SUBJECT=id(exposed) 这个写法。因为两个组里受试者编号都是从 1 开始，如果只写 id，暴露组的 1 号和对照组的 1 号会被当成同一个人，相关性就算错了。嵌套写进组里，才是真正的人。

非恒等链接：交互项不再等于均值之差

换成 logistic 模型：

LogOddsAB = λ + αA + βB + γAB

交互项仍然是一个差中之差，但它是 log odds 的差中之差。要在概率层面做同样的比较，得把四个 log odds 分别用 LOGISTIC 函数变回概率，再相减：

[logistic(λ+α+β+γ) − logistic(λ+β)] − [logistic(λ+α) − logistic(λ)]

这已经不是一个线性组合了，所以 ESTIMATE 和 LSMESTIMATE 算不出来。

用 LSMEANS / ILINK 能拿到四个格子的概率，但 ILINK 只作用于整条估计，一旦请求差（DIFF）或对比，反变换就不再适用。这就是为什么必须换工具。

三个能算均值层面 DID 的工具

同一个例子，logistic 模型下 log odds 的差中之差是 −1.1113，换成概率层面是 −0.26，置信区间 (−0.4497, −0.07028)，p = 0.0072。三种写法结果完全一样：

NLMeans 宏

需要两样东西：STORE 存下的模型，和 LSMEANS / E 经 ODS OUTPUT 存下的系数表。然后自己造一个对比数据集，变量名必须是 SET 和 K1…Kn：

data difdif;
   input k1-k4;
   set=1;
   datalines;
1 -1 -1 1
;
run;

%NLMeans(instore=log, coef=coeffs, link=logit, contrasts=difdif,
         title=Difference in Difference of Means)

NLEST 宏

直接把函数式写进 f=。参数名是 B_p1、B_p2 这样按参数估计表的顺序编号，截距是 B_p1：

%nlest(instore=log,
       label=Diff in Diff Means,
       f=( logistic(b_p1+b_p2+b_p4+b_p6) - logistic(b_p1+b_p4) ) -
         ( logistic(b_p1+b_p2)           - logistic(b_p1) ),
       title=Difference in Difference of Means)

Margins 宏

Margins 自己拟合模型，算出预测边际，再按你给的对比矩阵相减。对比矩阵写成数据集，必须有 LABEL 和 F 两个变量：

data c;
   length label f $32767;
   infile datalines delimiter='|';
   input label f;
   datalines;
A1-A0 | 0 -1 0 1, -1 0 1 0
Diff in Diff of Means | 1 -1 -1 1
;
run;

%Margins(data     = a,
         response = y,
         roptions = event='1',
         class    = a b,
         classgref= first,
         model    = a|b,
         dist     = binomial,
         margins  = a b,
         contrasts= c,
         options  = cl)

Margins 的输出更全：它同时给联合卡方检验和每一行的估计。上面这个例子里，B=1 时 A 的差是 0.07（p=0.3210，不显著），B=0 时是 0.33（p<0.0001，显著），两自由度联合检验也显著，最后差中之差 −0.26（p=0.0072）。

先看链接函数，再决定用哪条路

有协变量的时候

  • LS-means 的口径：连续协变量取均值，分类协变量按水平均衡加权，得到的是一个“标准人”上的差中之差。
  • 想在其它取值上算：LSMEANS 加 AT C=2.5；想按实际比例加权加 OM，比例不符就用 OM=数据集 指定一张比例表。
  • 想在各层分别算：模型里把协变量和 A、B 及它们的交互都放进去，写成 c|a|b，LSMEANS 变成 c*a*b，对比数据集按层写几行 1 -1 -1 1 就行。
  • 用 Margins 就不用管这些：预测边际是对观测到的协变量取值求平均，不是固定成均值，模型里带上协变量即可，也不需要 AT、OM。
