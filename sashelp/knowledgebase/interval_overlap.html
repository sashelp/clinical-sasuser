如何判定两个区间重叠？

两个闭区间的重叠天数 = min(两个终点) − max(两个起点) + 1；结果小于等于 0 就说明不重叠。

结论

设两个区间 [A1, A2] 和 [B1, B2]，两端都算，那么：
重叠长度 = min(A2, B2) − max(A1, B1) + 1
结果大于 0 就是共享的天数；等于 0 表示两个区间紧挨着、一天都不共享；小于 0 表示中间有空档，绝对值就是空了多少天。不关心空档就套一层 max(0, …)，一行搞定。

两个区间、四个端点，重叠段由“晚的那个起点”和“早的那个终点”夹出来

先把问题说清楚

这里的区间是闭区间：起点和终点都算在内。[1, 5] 包含 1、2、3、4、5 共五天。而且约定起点不晚于终点，也就是 A1 ≤ A2。

SAS 里日期是从 1960-01-01 起算的天数，本身就是一个整数；datetime 是秒。所以这套算法对日期完全适用，对任意整数区间也适用。

解法一：暴力数一遍

最直白的办法：从最早的起点循环到最晚的终点，逐天判断这一天是不是同时落在两个区间里。

data RESULTS;
   set EVENTS;
   OVERLAP = 0;
   do i = min(A1,B1) to max(A2,B2);
      if (A1<=i<=A2) and (B1<=i<=B2) then OVERLAP + 1;
   end;
run;

好处是不用动脑子，写出来就能对上；坏处是循环次数等于两个区间合起来跨了多少天。跨十年的两个区间就是三千多次循环，一行数据还好，几十万行就明显吃不消了。通常只把它当验证用的参考答案。

解法二：分情况写 if-then

把两个区间的相对位置拆成几种情形，每种情形单独算。代码长一点，但不循环。

data RESULTS;
   set EVENTS;
   if A1<=B1 and A2>=B2      then OVERLAP = B2 - B1 + 1; else
   if A1>=B1 and A2<=B2      then OVERLAP = A2 - A1 + 1; else
   if A1<=B1<=A2 and B2>A2   then OVERLAP = A2 - B1 + 1; else
   if B1<=A1<=B2 and A2>B2   then OVERLAP = B2 - A1 + 1; else
   if B1>A2 or A1>B2         then OVERLAP = 0;
run;

五个分支对应的位置关系：

情形条件重叠长度
A 完全罩住 BA1 ≤ B1 且 A2 ≥ B2B2 − B1 + 1
B 完全罩住 AB1 ≤ A1 且 B2 ≥ A2A2 − A1 + 1
A 先开始、B 后结束A1 ≤ B1 ≤ A2 且 B2 > A2A2 − B1 + 1
B 先开始、A 后结束B1 ≤ A1 ≤ B2 且 A2 > B2B2 − A1 + 1
不相交B1 > A2 或 A1 > B20

写的时候容易漏情形、也容易把边界写反（比如把 A1≤B1≤A2 写成 A1≤B1<A2，端点那天就丢了）。这种写法适合当中间过程，帮自己把问题想清楚。

解法三：一个公式

把上面五种情形合起来看，其实都是同一件事：重叠段的起点，是两个起点里较晚的那个；重叠段的终点，是两个终点里较早的那个。所以：

Overlap = min(A2, B2) − max(A1, B1) + 1

data RESULTS;
   set EVENTS;
   OVERLAP = min(A2,B2) - max(A1,B1) + 1;
   if OVERLAP < 0 then OVERLAP = 0;
run;

不想要那个 if，就用 max(0, …) 一步写完：

data RESULTS;
   set EVENTS;
   OVERLAP = max(0, min(A2,B2) - max(A1,B1) + 1);
run;

三种写法跑出来的结果

用文中的七组样例（日期是 2022 年 1 月）实际跑一遍，三种写法结果完全一致：

第四行值得看一眼：B 完全落在 A 里面，重叠就是 B 本身的长度 2 天。第六行只有 1 月 5 日这一天是共有的，因为两端都算在内，正好卡在边界上的那一天也算重叠。

为什么都要 +1

因为两个日期相减得到的是“中间隔了几天”，不是“包含几天”。1 月 3 日到 1 月 4 日，4 − 3 = 1，但这两天都算的话是 2 天。所以闭区间的长度一律是 终点 − 起点 + 1。

反过来，如果你的区间是半开的（含起点、不含终点，比如 [start, end)），那就不加 1。这两种约定混用，结果会差一天，而且很难发现。

0 和负数怎么读

公式不截断时，0 和负数是有信息量的：

  • 等于 0：两个区间不重叠，中间也没空档——一个结束的第二天，另一个就开始了。
  • 小于 0：中间有空档，绝对值是空了多少天。上面第二行是 −3，就是 1 月 18 日结束后，到 1 月 22 日开始之前空了 19、20、21 三天。

如果分析上只关心“重叠多久”，把负数抹成 0 就行；如果还要看“两个事件隔了多久”，就保留原始值，别急着截断。

实际用的时候几个坑

  • 单位要统一。datetime 变量存的是秒，直接套公式得到的是重叠秒数。要换算成天就除以 86400，或者干脆按秒比较，别一半用日期一半用 datetime。
  • 缺失值不会报错。SAS 的 MIN/MAX 函数忽略缺失值，四个端点里缺一个，公式照样算得出一个看起来正常的数。我试过把 A1 置空，公式返回 3，日志里一句提示都没有。所以先确认四个变量都不缺，再算。
  • 半开区间不要 +1。同理，如果数据里起点终点采用的是“包含起点、不包含终点”的约定，加 1 就多算了一天。
  • 月和年不能直接套。月份、年份长度不等，减出来的数字没有统一含义。要么先转成天数，要么用 INTCK 按需要的单位算。
  • 只想回答“有没有重叠”，不用算长度。闭区间下判断 max(A1,B1) <= min(A2,B2) 就够了，等价写法是 A1<=B2 and B1<=A2，一步出 0/1 标志。
  • 一个受试者多条区间时，要两两比较就用 SQL 自连接或 PROC SQL 的笛卡尔积按 USUBJID 限定，别在 DATA step 里写双重循环——数据量一大就跑不动。
