如何按 200 字节长度切分变量？

substr 按字节切，会把一个汉字劈成两半；改用 ksubstrb 按字节切并自动丢掉破字符，想不切断句子再用 kfindc 从右往左找标点。

结论

XPT V5 对字符型变量的长度上限是 200 字节，超长就得拆成几个变量。但 substr 是按字节切的，一个汉字在 UTF-8 里占 3 个字节，切在第 200 字节很可能正好劈开一个字，后半截字节不成字符，显示成乱码。用 ksubstrb 代替：它同样按字节切，但会把末尾不完整的字符自动丢弃。如果还想尽量避免把一句话拆到两个变量里，切完再用 kfindc(…,'b') 从右往左找最后一个标点，在那里截断。

为什么是 200

向 CDE 递交时数据集通常用 XPT（SAS Transport Format），建议 XPT V5 或以上。V5 格式有一条硬性限制：字符型变量的长度至多为 200。超过就得拆，拆出来的每一段也不能超过 200。

字符和字节不是一回事

一个字符在计算机里可能占 1 个到多个字节。以 UTF-8 为例：

字符类型字节数例子
数字、英文字母1A、7
欧洲字母、希腊字母2é、α
中、日、韩文字3汉、字
表情符号4😀

所以“200 字节”不等于“200 个字”。英文能放 200 个，中文最多只能放 66 个。这也是为什么按字节切的时候，边界经常落在汉字中间。

substr 是怎么切出乱码的

拿 汉字 举例，切前 4 个字节：

data _null_;
  x = substr('汉字', 1, 4);   /* 汉占 3 字节，第 4 字节是“字”的第 1 个字节 */
  put x=;
run;

结果是 汉 加上半个字符，那半个字节在当前编码里凑不成合法字符，屏幕上就是乱码。

换成实际的长文本更明显。一段 535 字节的中文，按 200 字节切三段，第一段末尾的字节是 E6 88——一个三字节汉字只拿到了前两字节，后面那段又从第三个字节开始，两段都读不出这个字。

直接照这个思路写程序，还有个小毛病：最后一段的起点可能已经超过字符串总长度，substr 会报“第三个参数非法”，并把 _ERROR_ 置 1。

data tab1;
  set raw;
  text_1 = substr(text, 1, 200);
  text_2 = substr(text, length(text_1)+1, 200);
  text_3 = substr(text, length(text_1)+length(text_2)+1, 200);
run;

把 substr 换成 substrn 可以消掉这个报错（起点越界时安静地返回空），但乱码管不了——两件事得分开解决。

修法一：ktruncate 丢掉破字符

ktruncate 干的就是这件事：把字符串末尾“破裂”的多字节字符部分切掉。套在 substrn 外面就行：

data tab2;
  set raw;
  text_1 = ktruncate(substrn(text, 1, 200));
  text_2 = ktruncate(substrn(text, length(text_1)+1, 200));
  text_3 = ktruncate(substrn(text, length(text_1)+length(text_2)+1, 200));

  length text_99 $1024.;
  text_99 = trim(text_1)||trim(text_2)||trim(text_3);
  comp = (text = text_99);
  put comp=;
run;

注意 length() 返回的也是字节数，所以 length(text_1)+1 这个起点会自动落到完整字符的开头——被丢掉的那两个字节，会在下一段开头被重新读进来，不会丢内容。实测这段：第一段从 200 字节被截到 197 字节，拼回去和原文完全一致。

修法二：ksubstrb 一步到位

ksubstrb 把两件事合在一起：按字节截取，同时自动丢掉末尾不完整的字符。语法和 substrn 一样：

data tab3;
  set raw;
  array _dummy_[3] $200. text_1-text_3;
  used_len = 1;
  do i = 1 to dim(_dummy_);
    _dummy_[i] = ksubstrb(text, used_len, 200);
    used_len + length(_dummy_[i]);
  end;
run;

数组声明 $200. 保证每个变量不超过 200 字节；used_len 记录下一段从第几个字节开始，每次加上刚切出来的字节数。这种写法比一句句抄三遍好维护，段数改了只改数组维度。

别把一句话切成两半

按固定 200 字节切，很可能把一句话从中间劈开。改善办法：切完一段后，在这段里找最后一个句末标点，从那里截断，剩下的留给下一段。

data tab4;
  set raw;
  array _dummy_[3] $200. text_1-text_3;
  used_len = 1;
  do i = 1 to dim(_dummy_);
    _dummy_[i] = ksubstrb(text, used_len, 200);
    _dummy_[i] = ksubstr(_dummy_[i], 1, kfindc(_dummy_[i], '，。？；', 'b'));
    used_len + length(_dummy_[i]);
  end;
run;

关键是 kfindc 的第三个参数 'b'：默认从左往右找，返回第一个标点的位置；加了 b 就从右往左找，返回最后一个标点的位置。实测一句 ab，cd。ef？gh；ij，正向返回 3，反向返回 12。

这个初版有三个坑，补丁版长这样

上面那段是照着一个固定例子写的，直接拿去用会出问题。我实测过：最后一段在标点处截断后，标点后面的内容就丢了，三段拼回去和原文对不上（comp=0）。原因是最后一段后面没有第四段来接手剩下的内容。

作者后来给了修订版，改了五处：

  1. len 挪到分割用的数据步里算，不污染原始数据集。
  2. 只有 len > 200 才进循环，短变量直接 text_1 = text。
  3. 每段切完先判断后面还有没有内容（used_len + 200 > len），没有了就直接跳出，最后一段不再按标点截。
  4. 标点集合扩到中英文的逗号、句号、冒号、分号、问号、感叹号和中文顿号。
  5. 只有这段里确实找到标点（kpos 非 0）才截断。
data tab4;
  set raw;

  len = length(text);
  array _dummy_[3] $200. text_1-text_3;
  used_len = 1;
  if len > 200 then do i = 1 to dim(_dummy_);
    _dummy_[i] = ksubstrb(text, used_len, 200);
    if used_len + 200 > len then leave;
    kpos = kfindc(_dummy_[i], '，。、：；？！,.:;?!', 'b');
    if kpos then _dummy_[i] = ksubstr(_dummy_[i], 1, kpos);
    used_len + length(_dummy_[i]);
  end;
  else text_1 = text;
run;

这一版实测三段拼回去和原文完全一致。

检查项结果说明

几个容易踩的点

  • length() 给的是字节数，不是字数。用它推位置没问题（和 ksubstrb 的字节定位配套），但别拿它当“第几个字”用，要做字符计数得用 klength()。
  • ksubstrb 起点越界也会置 _ERROR_=1，不像 substrn 那样安静返回空。所以循环次数要算准，或者像补丁版那样提前 leave。
  • 切出来的变量是定长的。声明成 $200.，短的那段末尾一堆空格，拼接前记得 trim 或 strip。
  • 中文标点也占 3 个字节（UTF-8 下），标点集合里别只写英文标点。
  • 编码环境会影响结果。同一段程序，在 EUC-CN 会话里汉字占 2 字节，能放的字符数完全不同；跑之前先确认会话编码，别拿 UTF-8 的数字套到别的环境。
  • 切分后要留校验。像示例那样拼回去和原变量比一次，是发现“丢了尾巴”这类问题最省事的办法。
