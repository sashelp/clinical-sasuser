知识库 / 统计分析

事件发生率不低的时候，怎么估计相对风险，而不是拿 OR 顶替？

OR 只在事件很罕见时才近似 RR；事件不少时，可以用 PROC FREQ 的 RELRISK、NLMeans 宏、log-binomial 模型，或者 Zou 的修正 Poisson。

结论

相对风险就是两个事件概率的比，多数时候比 OR 好解释。只有在事件罕见（比如低于 10%）时，OR 才近似 RR，可以拿来代替。事件不罕见时，四条路可选：不建模直接算 2×2 表、logistic 模型配 NLMeans 宏、log-binomial 模型、Zou 的修正 Poisson。日常最稳的是前两条；样本小、模型不好收敛时用第四条。

为什么不能把 OR 当 RR 用

举个具体的数：100 名男性里 30 人回答“是”，100 名女性里 45 人回答“是”。

  • 女性的风险 45/100 = 0.45，男性 30/100 = 0.30，相对风险 = 1.50
  • 优势比 = (45/55) ÷ (30/70) = 1.91

两个数差了 27%。原因很简单：整体事件率约 37.5%，一点也不罕见，OR 会把 RR 往外推。这种情况下报 OR 说“风险高了 91%”，是误导。

方法一：不建模，直接算

单个二分类预测变量，把数据摆成 2×2 表，用 RELRISK 就能同时拿到 RR 和 OR：

data question;
   input Gender $ Response $ Count;
   datalines;
Women Yes 45
Women  No 55
Men   Yes 30
Men    No 70
;
run;

proc freq data=question order=data;
   weight Count;
   tables Gender*Response / relrisk;
run;

ORDER=DATA 让 Yes 排在第一个列，于是 RR 出现在 Cohort (Col1 Risk) 那一行：1.50，置信区间 (1.0365, 2.1707)。如果顺序反了，读到的就是 1/1.5，方向搞错。

有分层变量时改用 CMH，把分层变量写在表定义的前面：

proc freq data=example2 order=data;
   tables strata*treat*outcome / cmh noprint;
run;

这条限制要记住：RELRISK 只在行变量只有两个水平时才能给 RR。

方法二：logistic 模型 + NLMeans 宏

logistic 模型能直接给的是 log odds，线性组合算不出概率的比。要拿概率的比，得对参数做非线性组合，NLMeans 宏把这件事封装好了。

先在 LOGISTIC 里拟合模型，用 LSMEANS / E ILINK 拿到每个性别的概率和对应的系数表，用 STORE 存下模型：

proc logistic data=question;
   freq count;
   class gender(ref="Men") / param=glm;
   model response(event="Yes")=gender;
   lsmeans gender / e ilink;
   ods output coef=coeffs;
   store out=ques;
run;

然后调宏。三个关键参数：options=ratio 让它算比而不是差，null=1 让零假设变成“RR = 1”，link=logit 告诉它模型用的链接函数：

%nlmeans(instore=ques, coef=coeffs, link=logit, options=ratio,
         null=1, title=Relative Risk)

估出来 RR = 1.5，95% 置信区间 (0.95, 2.05)，p = 0.0771。和直接算的 1.50 一致，区间略宽，因为用的是模型估计而不是原始比例。要反向的比（男/女），加 reverse。

底层还有 NLEST 宏，直接写函数式。同一个例子写成“女性的概率除以男性的概率”：

%nlest(instore=ques, label=Rel. Risk (Women/Men), null=1,
       f=logistic(b_p1+b_p2)/logistic(b_p1))

方法三：log-binomial 模型

换一个链接函数，RR 就变成了参数的直接指数。因为 log(p) = a + bx，x 增加一个单位时两个 log 概率相减就是 b，而 log(p1) − log(p2) = log(p1/p2)，所以 exp(b) 就是 RR。

proc genmod data=a;
   class a;
   model y(event="1") = x|a / dist=binomial link=log;
   weight f;
   lsmeans a / diff exp cl;
   estimate "RR (X+1)/X" x 1 x*a 1;
run;

这条路的问题是会不收敛。原因是 log 链接不保证预测概率落在 0 到 1 之间，极大似然解可能跑到参数空间边界上。实用上有两个补救：

  • 给截距一个负的起点：在 MODEL 语句加 INTERCEPT=-4。因为 0 < p < 1，必然有 log(p) < 0，从负数出发更容易找到解。
  • 把数据复制多份，再补一份响应取反的，把解从边界拉回参数空间内部。这样做参数估计是对的，但标准误会因为样本被复制而偏小，所以要按复制份数开方修正；更方便的做法是给权重做归一化，让权重和等于真实样本量。

文章里的示例就是这么干的：原始数据权重 10000，取反的数据权重 1，再统一乘 20/200020 归一化到 20 例。跑出来 X 每增加一个单位，事件可能性变成 1.23 倍。

方法四：Zou 的修正 Poisson

思路是：把二分类结局硬当成计数来拟合 Poisson 模型，用 REPEATED 得到稳健方差，这个稳健标准误正好是 RR 的标准误。

proc genmod data=example2;
   class id strata treat(ref="0");
   model outcome = treat strata / dist=poisson link=log;
   repeated subject=id;
   lsmeans treat / diff exp cl;
run;

28 天死亡率那组数据算出来 RR = 2.30，置信区间 (1.27, 4.15)。同一批数据换几种方法对比一下很有意思：

方法RR 估计95% 置信区间
Zou 修正 Poisson（GEE 稳健方差）2.301.27 – 4.15
Mantel-Haenszel（PROC FREQ CMH）2.281.27 – 4.09
log-binomial 模型1.941.05 – 3.59

三个数不完全一样，说明估计方法确实会影响结论。写报告时把用了哪种方法写清楚，比纠结哪个“最对”更重要。

四条路怎么选

情形推荐做法理由
一个二分类变量，不分层PROC FREQ + RELRISK不用建模，结果最直观
要调整多个协变量logistic + NLMeans 宏模型成熟、收敛稳定，代价是要装宏
样本量小、事件少Zou 修正 Poissonlog-binomial 容易不收敛，这个方法更稳
只想快速出一版log-binomial代码最短，exp(参数) 就是 RR
