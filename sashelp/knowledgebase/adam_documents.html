知识库 / ADaM

ADaM 的文档一大堆，到底该看哪几本、怎么配？

先定 ADaMIG 版本，再用对应的 Release Package 一整套拿；文档之间打架时以发布日期最新的为准，示例文档不是标准。

结论

不用一本本去挑。先决定用哪个版本的 ADaMIG，然后下载那个版本对应的 Release Package（一个 zip），里面就是这一版配套的全部文档，一套用就行。版本怎么定看申报对象：查他们的 Data Standards Catalog。文档之间出现说法不一致时，看发布日期的先后，以最新的为准。

为什么会有这么多文档

ADaM 团队的做法是把工作拆成小块，分给不同的小组，谁先做完谁先发布。这样做开发快了，代价是文档越出越多，新人一进来看花眼。

举一个具体例子就明白了：ADaMIG 里写了 ADSL 和 BDS 这两种结构的细节，但 OCCDS（发生事件数据结构）的细节要去另一份文档看。原因是 ADSL 和 BDS 从 2009 年就有了，OCCDS 一直到 2016 年才正式化。当时团队没有把 OCCDS 塞回 ADaMIG，而是单独出了一份文档。

Release Package：按版本打包

为了治这个乱，ADaM 团队给每个 ADaMIG 版本做了一个 zip，里面是打算配合使用的全部文档。以 ADaMIG v1.3 为例，包里有七份：

  • ADaM v2.1（2009-12-17）
  • Important Considerations When Using ADaM v2.1（2021-11-29）
  • ADaM Implementation Guide v1.3（2021-11-29）
  • ADaM Structure for Occurrence Data Implementation Guide v1.1（2021-11-29）
  • ADaM Implementation Guide for Non-compartmental Analysis Input Data v1.0（2021-11-29）
  • ADaM Implementation Guide for Medical Devices v1.0（2021-11-29）
  • ADaM Conformance Rules v4.0（2021-11-29）

v1.2、v1.1、v1.0 也各有自己的包，内容略有不同。

那份"Important Considerations"一定要先读

ADaM v2.1 是 2009 年出的，里面的类别、子类、元数据示例早就过时了。这份短文就是为了补这个洞：它把你引到更新的 CDISC 文档去看这些内容。用它之前先读这份，否则会照着一份十几年前的描述去建数据集。

版本对应关系

ADaMIG v1.1 及以后，第 1.3 节有一张图，列出每份文档适用于哪个 ADaMIG 版本。下面是从 v1.3 那张图整理出来的简表：

文档状态怎么用
ADaM v2.1（模型本体）基础文档所有版本都适用，但要配 Important Considerations 一起读
ADaMIG v1.3当前实现指南主文档，先定它
OCCDS IG v1.1适用做 AE、CM、MH 这类发生事件数据集时看
ADNCA v1.0（非房室分析）适用做 PK 参数数据集时看
ADaMIG-MD v1.0（器械）适用器械研究才用
BDS for Time-to-Event v1.0示例不是标准，参考写法
ADaM Statistical Examples v1.0示例不是标准，参考写法
Conformance Rules v4.0适用自查和跑校验工具时用

表里出现“Superseded by”的组合不要用。比如 ADaM Data Structure for Adverse Event Analysis v1.0 已经被 OCCDS 取代了，别再用。标着“Not written for”的要谨慎——不是不能用，而是那份文档成文时还没有这个 ADaMIG 版本，配套关系没有经过确认。

实际怎么选

  1. 先定 ADaMIG 和 Define-XML 的版本。这决定后面所有事情，别跳过。
  2. 看申报对象的要求。交 FDA 查 FDA 的 Study Data Standards Catalog，交 PMDA 查 PMDA 的目录，里面写明接受哪些版本。
  3. 考虑用最新的 ADaMIG。新版向后兼容做得很好：你可以用最新版里的新变量，申报时仍按旧版报，校验工具也按旧版跑。由此产生的少量差异（比如某个变量标签改了）在 ADRG 里说明一句就行，通常值得换取用上新内容的好处。
  4. 下对应的 Release Package。里面文档齐全，不用东拼西凑。

标准和示例要分清

ADaM 的文档分两类，混了容易出事：

  • 标准类：模型本体（ADaM v2.1）和各份 IG。它们规定什么能做、什么不能做。
  • 示例类：BDS for Time-to-Event、ADaM Statistical Examples，还有一些 TAUG 里的 ADaM 示例。它们演示怎么用标准里的结构和变量。

示例不是标准，不要求照做。它的价值是在你设计类似数据集时给个起点。不管参考哪个示例，ADaM 的基本原则还是要守。

文档打架怎么办

同一个概念在不同文档里都写过，而文档的发布日期不同，措辞就可能不一样。处理办法很简单：看发布日期，用最新的那份。老文档里过时的说法不代表现在的立场。

还有一句值得记住：这些文档未来会合并成更少、更一致的几份，但在那之前，信息就是分散的。
