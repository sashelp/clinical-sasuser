知识库 / SDTM

受试者中途换中心，SDTM 里怎么记？

在 DS 域加一条 DSCAT=OTHER EVENT 的记录，DSTERM 写清楚、DSDECOD=TRANSFERRED、DSPARTY=SITE、DSPARTYID 填新中心号，日期放 DSSTDTC。

结论

用 DS（Disposition）域，加一条处置记录，DSCAT = "OTHER EVENT"，DSDECOD = "TRANSFERRED"，转移对象写在 DSPARTY = "SITE"，转到哪个中心写在 DSPARTYID，日期放 DSSTDTC。这套做法最早是为 COVID 研究整理的，但任何研究的受试者换中心都能用。

为什么放 DS 而不是 DM

DM 里只有一个 SITEID，一个受试者一条记录，装不下“什么时候从哪转到哪”。而转中心本质是一个事件，有发生时间、有前后对象，正好是 DS 域的表达范围。

用 DS 还有一个好处：DSSTDTC 把时间点记下来了。这一点很关键，因为只在 DM 里加个补充限定符是表示不了时间的。

变量怎么填

变量填什么说明
DSCATOTHER EVENT不属于研究阶段结束、不良事件等常规类别
DSTERM描述性文字比如“受试者因原中心关闭转至其他中心”
DSDECODTRANSFERRED标准化的处置结果
DSPARTYSITE转移涉及的“一方”是中心
DSPARTYID中心编号转移结束时负责的中心，也就是新中心
DSSTDTC转移日期ISO 8601
DSEPCHGIY / 空是否由疫情导致；v3.4 起是标准变量

--PARTY 和 --PRTYID 这两个变量容易被误解成器械专用。它们确实最早是在器械研究的 DT（Device Tracking and Disposition）域里用起来的，但从 SDTM v1.4 起就存在于模型中，也不限定只能用在器械研究或某些域。这里是“受试者”从一个中心转到另一个中心，所以 DSPARTY 填 SITE、DSPARTYID 填中心号，逻辑是一样的。

示例里只放了转中心的记录，DSSEQ 故意跳着编，暗示每个受试者还有别的处置记录。真实数据里 DS 域当然要包含全部处置事件，转中心只是其中一条。

DM 里的 SITEID 怎么处理

受试者转中心后，DM 只有一个 SITEID 位置，有两种写法：

  • 加补充限定符：SITEID 填原中心，另加 SITEID1（SUPPQUAL）填新中心。
  • 标记为多中心：SITEID = "MULTIPLE"，然后把包括原中心在内的所有中心都放进 SUPPQUAL。

转多次就加 SITEID2、SITEID3，两种写法都能扩展。到底哪种更合适，不同监管机构的偏好可能不一样，有疑问就直接问。

注意：在 DM 里用补充限定符表示多个中心，表示不了转中心发生的时间。要时间，还是得看 DS 里的 DSSTDTC。
