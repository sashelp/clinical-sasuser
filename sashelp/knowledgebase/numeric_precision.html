知识库 / SAS 编程

为什么十个 0.1 加起来不等于 1？数值精度要选到哪一档？

因为二进制存不下 0.1 这种数，只能存一个非常接近的近似值；比较浮点数别用等号，要给容差，从外部数据库读数时还要留意 15 位这道坎。

结论

计算机用有限的二进制位去表示无限的实数，绝大多数小数只能存成近似值。所以有两个习惯必须养成：判断两个浮点数是否相等，用容差而不是等号；需要精确的十进制值（金额、剂量、检验值），存成字符或者定点数，不要靠浮点。至于精度选到哪一档，取决于你的数据本身有几位有效数字，以及下游系统能接住几位。

哪些环节会让结果不一样

同一段程序，换台机器、换个版本跑出来末位不同，是很常见的事。能造成差异的地方有这么几处：

  • 硬件本身的限制，比如浮点运算单元的位宽
  • 操作系统的差异
  • 软件不同，或者同一个软件的不同版本
  • 不同的数据库管理系统
  • 用有限的数集去表示无限的实数——这一条是所有问题的根
  • 数字怎么存，存多长
  • 上面这些环节之间的转换怎么做

有的数存得准，有的存不准

10.25 用二进制写得下，所以是精确的：

data x;
   x=10.25;
   put x hex16.;
run;

输出 4024800000000000，一个干净的结尾。

10.1 就不行，写出来是一串 3：

data x;
   x=10.1;
   put x hex16.;
run;

输出 4024333333333333。这个值已经很接近 10.1，但不等于 10.1。后面所有的“怪现象”，源头都在这里。

同一段程序，换个平台末位就变了

把存不准的数拿去做加减，误差会被放大。下面这段先算出 10.1，再加上 100000 又减回去：

data x;
   x=10.1;
   put x hex16.;
   y=100000;
   newx=(x+y)-y;
   put newx hex16.;
run;

在 Windows 和 Linux 上，newx 是 4024333333333333，和原来的 10.1 一样；在 Solaris x64 上，它是 4024333333334000，末位变了。这不是 SAS 的问题，是硬件浮点宽度不同带来的，也没有办法彻底消除。

显示精度也会骗人

同一个数，格式不同，打印出来能差一位：

data;
   x=input('C047DFFFFFFFFFFF', hex16.);
   put x= 8.1 x= 8.3 x= 8.5 x= hex16.;
run;

在 Windows 或 Linux 上得到 x=-47.8，在 Solaris x64 上得到 x=-47.7，而用 8.3、8.5 打印时两边都是 -47.750。低精度格式（这里是 8.1）会先做一次舍入，平台之间舍入方向不一致，结果就差出来了。要避开这个问题，把格式放宽一位，用 8.2。

用等号筛记录，会漏数据

这是实际工作中最容易踩的一脚。下面这批数据里有两条 x，一条是精确的 5.2，另一条是算出来“差不多 5.2”：

data z(keep=x);
   x=5.2;
   output;
   y=1000;
   x=(x+y)-y;
   output;
run;

打印出来两行都是 5.2，肉眼看不出区别。可是用等号去筛：

data z1;
   set z(where=(x=5.2));
run;

在 Windows 上读到 2 条，在 MVS 上只读到 1 条。因为等号比较的是二进制值，那条“差不多 5.2”的记录在 MVS 上确实不等于 5.2。

正确的写法是给一个容差：

data z1;
   set z(where=(compfuzz(x,5.2,1e-10)=0));
run;

COMPFUZZ 返回 0 表示在容差范围内相等，这次两边都能读到 2 条。这个函数从 SAS 9.2 开始提供。

实际怎么处理

场景做法
判断两个浮点数相等 用 COMPFUZZ；9.2 以前没有这个函数，自己写一个容差比较的宏
用等号做子集、做 merge 的 key 先把参与比较的数值 round 到业务需要的小数位，或者改成字符再比
金额、剂量、检验值要精确 用 round(x, 0.01) 定下来再比较或输出，不要指望原始浮点值
从 Oracle 之类的外部库读数 数据库里的 NUMBER 能精确到 38 位，SAS 只到 15 位左右，超出的部分会丢；建库时选 BINARY_DOUBLE（15 位）比 NUMBER 更匹配
只是搬运不需要计算的大数 用 DBSASTYPE= 把列按字符读进来，原样保留位数

9.2 以前的版本可以套一个容差比较的宏，思路就是算相对误差：

%macro eqfuzz(var1, var2, fuzz=1e-12);
   abs((&var1 - &var2) / &var1) < &fuzz
%mend;

data _null_;
   x=0;
   y=1;
   do i=1 to 10;
      x+0.1;
   end;
   if x=y then put 'x exactly equal to y';
   else if %eqfuzz(x,y) then put 'x close to y';
   else put 'x nowhere close to y';
run;

这段跑完打印的是 x close to y——十个 0.1 加出来不是 1，但在容差范围内算相等。

搬运大数的时候，把列按字符读进来就不会掉精度：

libname ora oracle user=scott password=tiger path=path;

data sasdata;
   set ora.catalina2( dbsastype= ( c1='char(20)') );
run;
