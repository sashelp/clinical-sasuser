SUPPQUAL 里的 QNAM，要不要以域代码开头？

一般观察类的域建议带，DM 不必带，SV 建议带 SV 前缀；SDTMIG 原文写的是“不要求”，带上是为了以后省事。

结论

SDTMIG 附录里写得很清楚：QNAM 的 2 字符域代码不是必需的。但同一个附录里列出的那些 QNAM 值，其实全都带着域代码。所以实践中的做法是：一般观察类的域，QNAM 带上域代码；DM 不必带；SV 建议带 SV 前缀。理由不是标准强制，而是带上以后后面省事。

标准原文和实际做法的落差

SDTMIG 有一个附录专门列 Supplemental Qualifiers Name Codes，也就是 QNAM 的取值。附录里的说明是“the 2-character domain code is not required”，但你看它后面列出来的 QNAM，基本都带着域代码。

这就造成一个现象：SDTMIG 和各个 TAUG 的例子里，有的带、有的不带，看例子的人就不知道该跟哪个。

NSV Registry 为什么建议带上

CDISC 的非标准变量注册团队（NSV Registry Team）一直在整理这些补充限定符，他们的建议是一般观察类的 QNAM 包含域代码。两个理由都很实在：

  1. 将来可能“转正”。如果某个非标准变量哪天被收进标准，成为正式的 SDTM 变量，带域代码的 QNAM 可以直接沿用；不带域代码的就得改，一改，历史数据和程序都要跟着动。
  2. 避免撞车。QNAM 只有 8 个字符，如果前两个字符碰巧和某个域代码一样，读的人会以为它是那个域的变量。现在的 SDTMIG 里没有，不代表以后的版本里不会有。

哪些域会有补充限定符

除了一般观察类，能挂 SUPPQUAL 的域很少：

  • Demographics（DM）：一直都可以。
  • Subject Visits（SV）：SDTMIG v3.4 起明确可以。

DM：不用带 DM 前缀

DM 域的标准变量本身就不以 DM 开头，只有 DMDTC 和 DMDY 两个例外。历史上的 DM 补充限定符也没带过前缀，比如 RACEOTH（其他种族）、RACEOR（原始种族）。所以给 DM 加补充限定符时，硬加一个 DM 开头反而和这个域的惯例不一致。

SV：建议带 SV

SV 域除了 STUDYID、USUBJID、VISITNUM、VISIT、VISITDY 这五个，其余变量全以 SV 开头。既然整个域都是这个习惯，SV 的补充限定符也从 SV 开头比较自然。

一张表记住

域QNAM 要不要带域代码为什么
一般观察类（AE、LB、VS、CM、EX、PR 等）建议带将来转标准可直接沿用；避免前两字符被误读成域代码
DM不必带DM 的标准变量本身就不带 DM 前缀，历史补充限定符也没带
SV（v3.4 起）建议带 SV该域除 5 个变量外全部以 SV 开头

落地时的两点

  • 同一个域里保持一致。别一半带、一半不带，reviewer 会问为什么。
  • QNAM 是 8 字符上限。带上域代码只剩 6 个字符可用，命名要提前想好，别到后面缩写到看不懂。
