知识库 / 临床提交

药物临床试验资料递交是否要求程序文件可复现？

是。CDE 要的是“能直接重现出和申办方一致的统计结果”，FDA 靠“可追溯 + 交源代码”达到同样目的。

结论

不管是交给 CDE 还是 FDA，要求其实指向同一件事：你交的程序得能跑通，监管的人能拿它把分析数据集和关键图表重新算出来。两家说法不一样——CDE 直接写“可追溯、能重现”，FDA 写“traceability + 交源代码”，但落点完全一致。

CDE 怎么说的

《药物临床试验数据递交指导原则（试行）》（2020 年 7 月）里，有两句话最要紧。

第一句，讲可追溯性

“申办方在递交数据库时应确保监管部门能够利用原始数据库衍生出与申办方一致的分析数据库，利用分析数据库能够直接重现出与申办方一致的统计分析结果。”

这句话说白了，就是把“能复现”定成了递交的底线。同一节还列了审评人员要能做的四件事：看懂分析数据集怎么建的；知道每个衍生变量用了哪些原始记录、什么算法；看懂统计结果怎么算的；能把原始数据一路对到报表。

第二句，讲程序代码

“申报资料中递交的程序代码应当易懂、可读性强，建议提供充分的注释、避免外部（宏）程序调用。”

程序代码要覆盖两块：分析数据集的衍生过程、疗效指标的分析过程。这正好对应“复现分析数据集 + 核心疗效图表”这两件事。

小结：CDE 没说“必须一键重跑”这么死板的话，但“直接重现出与申办方一致的统计分析结果”这句，已经把“能跑、能复现”变成硬要求了。

FDA 怎么说的

《Study Data Technical Conformance Guide》里也有两处对应。

第一处，讲 traceability

“Traceability permits an understanding of the relationships between the analysis results (tables, listings and figures in the study report), analysis datasets, tabulation datasets, and source data.”

意思是审评员要能搞清楚：分析数据集怎么建的；衍生变量用了哪些观测记录和算法；某个置信区间或 p 值是怎么算出来的；报告里每张表、每个数字都能对回底层数据。

第二处，讲程序文件

“Sponsors should provide the source code used to create all ADaM datasets, tables, and figures associated with primary and secondary efficacy analyses.”

同时要求：源代码用单字节 ASCII 文本，别交 .cmd、.com、.exe 这类可执行文件；用的软件版本和操作系统要写进 ADRG。

小结：FDA 没直说“必须能复现”，但它靠三件事把同一目的落实了：强制交源代码；要求结果能对回底层数据、算法能看懂；在“遗留数据转换的可追溯性问题”清单里，反复把“复现不了分析数据集”列为典型问题。等于变相告诉你——数据要是复现不出来，就是问题。

从头到尾的链路

数据一路从原始走到统计结果，每一步都得能对上

对你意味着什么

  • 程序能跑通是前提。CDE 那句“监管能衍生出一致的分析数据库、直接重现一致的结果”，前提就是你的程序在人家环境里跑得起来。所以代码要自包含、能执行：别调外部宏、路径别写死、环境依赖写清楚。
  • 核心图表必须能复现。CDE 的“疗效指标分析结果的生成过程”、FDA 的“primary and secondary efficacy analyses 的表和图”，都指向主/次要疗效终点的表和图的代码必须交、必须能追溯。安全性的关键图，比如 K-M 曲线、主要终点森林图，也一样要能复现。
  • 做的时候记住这几条：代码注释写足，每步逻辑和衍生规则讲清楚；别依赖外部宏、外部库、特定盘符；软件版本、操作系统、编码、程序调用顺序写进数据审阅说明或 ADRG；SDTM 到 ADaM 到输出图表的每一步都有对应代码、都能追溯；中文环境注意标签和编码统一。
