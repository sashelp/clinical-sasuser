知识库 / SAS 编程

在宏里写注释，为什么一个星号会把后面的代码也吃掉？

三种注释走三条不同的解析路径：斜杠星号逐字符读，星号和百分号星号都是读到分号为止。宏里只用斜杠星号，就不会出这种事。

结论

宏定义里写注释，只用 /* 注释 */。星号注释和宏注释都是“一路读到分号为止”，中间碰上引号、%、& 还会按各自的规则继续解析，很容易把后面几条语句一起吞掉，最后报一个看不懂的 ERROR 180-322。

三种注释，三种读法

SAS 处理一段代码要过好几道工序，不同的注释写法在不同工序上被处理，行为就完全不一样了。先认识一个词：token，也就是“词”。SAS 把代码切成一个个有意义的词，名字、数字、字符串、特殊符号各算一类，一个词不能再往下拆。

写法谁在处理怎么读什么时候出事
/* … */ word scanner 逐字符读，见到 */ 就停 基本不出事，引号和 %、& 都当普通字符
* … ; tokenizer 逐词读，读到分号停；引号在这里不算字符串，只是一个普通符号 写进宏定义后，整段先被当成常量文本收起来，规则又变了
%* … ; 宏设施 逐词读，读到分号停；引号会组成字符串，必须成对 注释里有一个撇号，就会一路吃下去

关键差别在最后一行：斜杠星号是逐字符，另外两种是逐词。逐词就意味着“要等一个分号”，而分号在 SAS 代码里满地都是。

星号注释怎么把 DATA 语句吃掉的

看这段宏：

%macro one;
   * This is a test %let x = this would not work;
   data new;
      set one;
   run;
%mend;
%one

编译这个宏的时候，SAS 从 %macro 一路扫到 %mend，把内容分成两类：宏语句（%let、%do 这些）当成待执行的代码，其余的都是普通文本，等调用时再推出去。

  1. * This is a test 这一段被当成普通文本收起来。
  2. %let x = this would not work; 被识别成宏语句，先执行掉，宏变量 x 就这么建出来了。
  3. 剩下的 data new; set one; run; 继续当文本收着。

真正调用 %one 的时候，这些文本被依次推到输入流里。第一段 * This is a test 推出来之后开始找分号结束注释，可它自己后面没有分号，只能继续往下吃，于是 data new; 的分号成了注释的终点——DATA 语句就这么变成注释的一部分了。剩下 set one; 孤零零留在外面，直接报错：

ERROR 180-322: Statement is not valid or it is used out of proper order.

很多人看到这个错会去查 SET 语句写错没有，其实问题在两行之前的那个星号。

宏注释碰上撇号，更隐蔽

%macro test(dsin);
   %* Shouldn't the single quotation mark be ignored since comment?;
   proc print data=&dsin;
   run;
%mend;

%* 是由宏设施逐词读的，引号在这里要组成字符串，所以必须成对。读的过程是这样：先拿到 Shouldn，接着遇到那个撇号，宏设施认为“字符串开始了”，开始找下一个撇号。可注释里只有这一个撇号，后面整段代码里也没有，于是它就一直往下读，把 proc print、run、%mend、后面所有提交的代码全并进这个字符串里。日志里只会给你一句提示：

WARNING 32-169: The quoted string currently being processed has become
       more than 262 characters long. You may have unbalanced quotation marks.

到这一步，宏已经不成立了，但报错位置离真正的原因很远，非常难查。同样的注释改成 /* Shouldn't ... */ 就一点问题没有，因为斜杠星号是逐字符读的，撇号只是个普通字符。

宏注释里有引号时会发生什么

实际怎么用

  • 宏里统一用 /* */。这是唯一一条必须记住的规矩，其余都是它的理由。
  • 临时屏蔽一段代码，也用 /* */。星号注释只适合顶格写一行说明、且内容里没有引号和宏触发符的场合，实际写起来很难保证。
  • 注释里想写什么就写什么。/* */ 里面出现撇号、引号、%let、&var 都没关系，它们不会被执行，也不会开一个字符串。
  • 看到 ERROR 180-322 先往回找注释。特别是错误位置指向一条看起来完全正常的 SET 或 DATA 语句时，往上翻几行，多半有个没写分号的星号注释。
  • 看到 WARNING 32-169 不要只盯着引号。代码里明明没有不配对的引号却报这个警告，就去检查宏注释里有没有撇号，比如 don't、shouldn't 这种英文缩写。
