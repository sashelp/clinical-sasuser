知识库 / SDTM

CDASH 里的 PRIOR / ONGO，怎么落到 SDTM 的相对时间变量上？

有日志的起止日期或访视，就用 --STTPT/--STRTPT 和 --ENTPT/--ENRTPT，不用 --STRF/--ENRF；没有日期才退回 --STRF/--ENRF。

结论

分两种情况。日志页面（比如既往用药、病史）如果记录了开始和结束的日期或访视，就用 --STTPT + --STRTPT 和 --ENTPT + --ENRTPT，把 PRIOR / ONGO 填进“相对参照时间点”的那两个变量里，这时不需要也不应该用 --STRF/--ENRF。如果起止日期和访视都没记，才退回用 --STRF 和 --ENRF，按日志采集期和研究参照期的位置关系取值。

情况一：日志的起止有记录

这是最理想的情况，四个变量一一对应：

采到的信息SDTM 变量说明
日志开始那天的日期或访视--STTPTStart Time Point，具体的时间点
开始时间相对参照期是“之前”还是“进行中”--STRTPTStart Relative to Reference Time Point，填 PRIOR 或 ONGOING
日志结束那天的日期或访视--ENTPTEnd Time Point
结束时间相对参照期的位置--ENRTPTEnd Relative to Reference Time Point

为什么这时候不用 --STRF/--ENRF？因为这两个变量是“没有具体时间点”时的近似表达，一旦有了确切日期，再同时填 STRF 和 STTPT，审阅的人会问哪个为准。

情况二：只有 PRIOR / ONGO 的勾选

实际数据里，日志的起止日期或访视经常没记。这时才用 --STRF（开始相对参照期的位置）和 --ENRF（结束相对参照期的位置）。

参照期就是 DM 里的 RFSTDTC 到 RFENDTC 这一段。判断依据是：日志采集的那段时间，和参照期比，是落在前面、里面、还是后面。

五种情形对照

下面这张表来自原文的示意图。左列是日志起始时采集到的 CDASH 值，右列是日志结束时采集到的值。

情形日志采集期与参照期的关系怎么填
1 完全重合 PRIOR=Y → STRF="BEFORE"；ONGO=Y → ENRF="AFTER"；ONGO=N → ENRF="BEFORE"
2 只在参照期开始时采集一次（比如入组时的病史） PRIOR=Y → STRF="BEFORE"；ONGO=N → ENRF="BEFORE"；ONGO=Y → ENRF="DURING/AFTER"
3 起点在参照期之前，终点在参照期之后 PRIOR=Y → STRF="BEFORE"；ONGO=Y → ENRF="AFTER"；ONGO=N → ENRF="BEFORE"
4 起点在参照期之前，终点在参照期结束之前 PRIOR=Y → STRF="BEFORE"；ONGO=N → ENRF="BEFORE"；ONGO=Y → 先等后续更新，最终可能是 DURING 或 AFTER，填 "DURING/AFTER"
5 起点在参照期之后 PRIOR 无法准确翻译成 STRF 或 ENRF

表里出现的 BEFORE、DURING、AFTER、DURING/AFTER 都是 --STRF/--ENRF 的受控术语取值。DURING/AFTER 这个看起来别扭的值，就是为“当时还确定不了是期内还是期后”准备的。

第 5 种情形为什么麻烦

日志在参照期之后才开始，意味着起始时间点在参照期后面。可 CDASH 的 PRIOR 只回答“是不是之前”，回答不了“之后”这件事，所以翻译不过去。

好在它很少见：日志数据几乎总是在研究参照期开始之前就开始采集了。真碰上，别硬凑一个值，在 define.xml 或 reviewer guide 里说明，或者回到原始数据确认时间点。

实操建议

  • 先确认参照期。不同研究对 RFSTDTC 的定义可能不一样（首次给药？知情同意？），填之前先对齐，否则整批 STRF/ENRF 都会偏。
  • 不要两套都填。有了 --STTPT 就别再给 --STRF，重复表达反而制造歧义。
  • ONGO 的更新要有机制。情形 4 里“等后续更新”意味着数据截止时可能还没定论，需要在数据管理流程里留一个回头更新的动作。
