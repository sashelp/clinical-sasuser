知识库 / ADaM

制作 ADaM 数据集时，哪些 SDTM 变量需要保留？

只要参与了 ADaM 衍生、或者能帮助追溯的 SDTM 变量，都应该保留；VSTESTCD 会映射成 PARAMCD（信息保留、列名换掉）。

先给结论

问题结论
VSTESTCD 这个原始列名要不要保留？不需要，把它映射成 PARAMCD（信息保留、列名换掉）
VSSEQ 要不要保留下来增强可追溯性？不是必需，但保留有价值，属于“推荐”而非“必须”
什么样的 SDTM 变量不需要保留？对分析无意义、纯技术性/内部管理性的变量

判断的基准

FDA 的《Study Data Technical Conformance Guide》在 ADaM 章节有两句话，就是我们判断“留不留”的尺子：

“To ensure traceability, all SDTM variables utilized for variable derivations in ADaM should be included in the ADaM datasets when practical.”——为了保证能追溯，凡用来做 ADaM 变量衍生的 SDTM 变量，只要可行，都应该带进 ADaM。

“For traceability purposes, SDTM character dates formatted as ISO 8601 should also be included in the ADaM datasets.”——为了能追溯，SDTM 里 ISO 8601 格式的字符型日期也要一起带进 ADaM。

这两句话给了同一个标准：判断“留不留”不是看变量好不好看，而是看它有没有参与衍生、有没有帮助追溯。

判断顺序

拿到一个 SDTM 变量，这么判断留不留

逐条说清楚

1. VSTESTCD 要不要保留？

原始列名不用留，把它映射成 PARAMCD 就行。原因是：

  • 它在 ADaM 里已经有了标准对应变量——VSTEST/VSTESTCD 映射成 PARAM/PARAMCD，信息已经带过来了，没必要再留一个重复的 VSTESTCD 列。
  • 跨域没法统一：ADaM 常常合并多个 SDTM 域，要是用原始列名 VSTESTCD，合并别的域时这列就没有了；PARAMCD 才是所有结果类数据集通用的必需变量。
  • 可追溯性不是靠“保留原列名”实现的，靠的是两样：PARAMCD 和 VSTESTCD 的取值对应关系（写进 Define-XML），再加上 SRCDOM/SRCSEQ/SRCVAR 这套溯源变量。

一句话：保留的是信息（参数代码），换掉的是列名（VSTESTCD 变成 PARAMCD）。

2. VSSEQ 有没有必要保留？

不是必需，但留了有好处，属于“推荐但不强制”。

  • --SEQ（比如 VSSEQ）在 SDTM 里是记录序号，是给每条记录的唯一内部标识，本身不是临床分析变量。
  • ADaMIG 把 --SEQ 定位成 permissible，不是 required。
  • 但留它有实实在在的好处：当同一个受试者、同一次访视、同一个参数有多条 SDTM 记录（重复测量、ECG 复测）时，--SEQ 能精确定位“ADaM 这条衍生记录对应 SDTM 哪一条源记录”。

实操建议：大多数场景用 SRCDOM + SRCSEQ（或者直接留 --SEQ）做一对一溯源就够了；担心重复测量对不上号的时候，建议保留 --SEQ 或改用 SRCDOM/SRCSEQ/SRCVAR 这套标准溯源变量，而不是硬留一个原始 VSSEQ 列名。

3. 什么样的 SDTM 变量“不用”保留？

还是回到 FDA 那把尺子：“不参与任何衍生、也不影响追溯、对分析没意义”的变量，可以不保留。常见的有这么几类：

类别例子为什么不留
纯技术/内部管理性序号没有重复场景下的 --SEQ、--SPID不参与分析、无追溯价值
已被 ADaM 衍生变量取代的原始字段原始字符日期（如果 ADaM 已经用数值 ADY/ADT）被衍生变量覆盖；但 ISO 8601 字符日期例外，见下
与当前分析无关的采集字段试验特定、但本次分析用不到的 --ORRES 补充字段对分析没贡献
为 SDTM 结构完整性存在的辅助变量排序变量、控制术语映射变量不承载临床信息

有个反直觉但 FDA 特意强调的点：SDTM 里 ISO 8601 格式的字符型日期（比如 VSDTC、AEDTC）建议保留，哪怕 ADaM 里已经有了数值型的日期/天数变量。因为字符日期是“原始采集状态”的直接体现，留了它，审评员才能核对“数值日期（ADY/ADT）是怎么从原始日期算出来的”。日期类原始字段别轻易当冗余删掉。
