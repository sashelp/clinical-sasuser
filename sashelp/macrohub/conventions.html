开发约定

本文约定本库自研宏程序的写法。opensource/ 目录下的宏是引入或独立维护的第三方代码，不适用本文的统一风格要求，保持原样即可。

1. 适用范围与命名

  • 目标运行环境为 SAS 9.4M7；不要使用更高版本才有的语法或选项。
  • 宏名用小写、单词间用下划线分隔，含义要能看出对象和动作，例如 ds_zipvarlen、stat_summaryn。
  • 文件按主题放在 dev/<主题>/ 下：变量 var/、数据集 ds/、逻辑库 lib/、目录 dir/、文件 file/、CDISC cdisc/、统计 stat/、开源 opensource/。
  • 一个文件只放一个宏；文件名与宏名一致（<宏名>.sas）。
  • 宏声明可选用 des= 描述，方便在 SAS 会话里查看用途。

2. 头部注释块

每个宏文件必须以块注释开头，字段顺序固定，缺项写 NULL 或 none：

/*
*Brief      : 一句话说明宏做什么
*Param(Req) : (DATA=)   输入数据集名
*Param(Opt) : (OUT=&DATA.)  输出数据集名
*Detail     : 返回值或输出数据集的细节、排序、保留策略
*Note       : 使用前提、边界条件、缺失值约定
*Usage      : 示例见站点的用法示例
*Dependency : %var_exist, %var_coexist
*Version    : SAS 9.4M7
*History    : YYYY-MM-DD, Author, Original version
*History    : YYYY-MM-DD, Author, 本次修改内容
*/

约定：

  • 参数注释必须与实际默认值和可接受取值一致；枚举型参数在注释里列出全部合法值。
  • 续行与首字段左对齐，保持 *字段名 起头，便于脚本解析。
  • Dependency 只写直接依赖的宏名，用 % 前缀、逗号分隔；没有依赖写 NULL。
  • History 每行一条，日期 YYYY-MM-DD，按时间从旧到新追加，内容写"改了什么、为什么"。
  • 头部注释是详情页"参数说明 / 注意事项 / 修订记录"的唯一依据，改代码必须同步改注释。

  • 所有工作变量用 %local 声明，包括错误信息、文件句柄、循环变量；名字要能看出用途。
  • 不要用全局宏变量做中间状态；不要依赖调用者会话里的残留值。
  • 返回值的宏用 &result. 作为最后一行；过程式宏不要"顺便"返回值。

4. 参数校验与错误处理

主处理开始前完成全部校验，顺序固定：

统一错误路径：

%let errtext=ERROR: Parameter DATA= not specified.;
%exception:
%if %bquote(&errtext.)^=%str() %then %do;
  %put &errtext.;
  %abort cancel;
%end;
  • 错误信息以 ERROR: 开头，写清楚是哪个参数、期望什么、实际得到什么。
  • 不要对非法输入静默取默认值，也不要吞掉失败；能失败的地方检查返回码，必要时用 %sysfunc(sysmsg()) 把系统信息带出来。
  • 校验分为多个独立 %if 时，注意 %else 链会短路；需要全部报告时拆成独立判断。
  • 宏声明里用到 in 运算符时，必须加 /minoperator 选项。

5. 处理逻辑

  • 优先用可读的 DATA 步 / PROC 步和 SAS 函数，不要生成难以维护的宏代码。
  • 宏值可能含特殊字符（引号、括号、逗号、空格）时，用 %quote / %bquote / %qscan / %qsysfunc 保护。
  • 输入数据集默认只读；只有文档明确允许时才覆盖输出。输出排序、保留变量、值映射都要在 Detail 里写清楚。
  • 按 BY 组处理前，显式按完整 BY 键排序，不要假设多个子集拼接后仍有序或仍交错。
  • 明确写出边界假设：唯一性要求、缺失值约定、ISO8601 不完整日期的处理方式。
  • 不要写死本机路径、libref 或目录；路径一律通过参数传入，或由调用方先分配逻辑库。

6. 清理与收尾

  • 中间数据集统一用固定前缀的 WORK 名称，正常退出前删除： 
/*3. Cleanup and exit*/
proc datasets mtype=data nowarn nolist;
  delete <中间数据集>;
quit;
  • 用 PROC DATASETS 配合 NOWARN / NOLIST：没有中间数据集时不产生多余警告和日志。
  • 不留调试输出、临时格式、临时 fileref；出错退出前也要尽量释放已打开的资源。
  • 宏中途 %abort cancel 时，尽量保证已创建的中间数据集不会残留。

7. 依赖与复用

  • 依赖的宏必须存在且已声明；构建站点时会按 Dependency 与宏体里的调用推导依赖闭包，漏声明会被提示。
  • 复用前先确认语义：%var_exist / %var_coexist / %var_attr 的 DATA= 只接受数据集，不支持视图。
  • 被依赖的宏必须能单独编译；不要在宏内部 %include 别的源文件。

8. 修订记录

  • 每次改动追加一条 *History，同时更新站点详情页的"修订记录"表格，两处内容与日期必须一致。
  • 只做注释/文档修订时也要记录，写明"更新文档说明：……"。
  • 破坏性改动（改默认值、改输出结构、改参数含义）要在记录里明确写出影响。

9. 测试

  • 每个宏在 qc/<主题>/<宏名>/ 下有验收测试：*_test.sas（正向用例）、*_err_NN.sas（负向用例，期望 %abort cancel）、*_bug_*.sas（缺陷回归）。
  • 正向用例至少覆盖：典型输入、空输入、边界值、无依赖与有依赖两条路径。
  • 负向用例用 *EXPECTED_ERROR: 注释声明期望的错误文本。
  • 改动后在 SAS 9.4M7 实机跑一遍，确认日志无 ERROR、无未预期 WARNING。
  • 测试程序不得依赖固定绝对路径；通过测试框架的路径变量定位宏源文件。

10. 交付前检查

  • [ ] 头注释字段齐全，参数注释与代码一致
  • [ ] 宏体按 1/2/3 分段，工作变量全部 %local
  • [ ] 校验完整，错误路径统一 %put + %abort cancel
  • [ ] 依赖已声明且可单独编译
  • [ ] 中间数据集已清理，未残留调试代码
  • [ ] *History 已追加，且与站点详情页的修订记录一致
  • [ ] QC 正向 / 负向 / 回归用例通过
